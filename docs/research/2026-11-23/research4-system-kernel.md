## Why this candidate exists

The [research3 candidate](research3-system-kernel.md) enabled `BPF_LSM` and BTF
but retained `FUNCTION_TRACER=n`. The
[source-level ARM64 trampoline audit](arm64-bpf-trampoline.md) found that native
kernel function entry is patched through ftrace on this architecture. Its
fallback `bpf_arch_text_poke()` only accepts JIT BPF program text. Research4
therefore enables the architecture's actual function-entry path in a new
source/output prefix; research3 remains intact for the runtime comparison.

| Resolved configuration | Research4 |
| --- | --- |
| `CONFIG_FUNCTION_TRACER` | `y` |
| `CONFIG_DYNAMIC_FTRACE` | `y` |
| `CONFIG_DYNAMIC_FTRACE_WITH_ARGS` | `y` |
| `CONFIG_DYNAMIC_FTRACE_WITH_CALL_OPS` | `y` |
| `CONFIG_DYNAMIC_FTRACE_WITH_DIRECT_CALLS` | `y` |
| `CONFIG_FTRACE_MCOUNT_RECORD` | `y` |
| `CONFIG_FTRACE_MCOUNT_USE_PATCHABLE_FUNCTION_ENTRY` | `y` |
| `CONFIG_FUNCTION_GRAPH_TRACER` | `n` |
| `CONFIG_UPROBE_EVENTS` | `n` |
