## What was verified

The existing project key and public certificate were present as regular files in the frozen research2 build directory. The private key was read only by the existing 6.12 `scripts/sign-file` program, with `sha512`, to sign a **new copied module**. It was not generated, copied, printed or included in a hash inventory. Its recorded size/mtime were unchanged afterward. The staged certificate files contain only public certificate data.

The public DER certificate's SHA-256 is:

```text
6ee402403dbba5b40e6c0012aa5271b20b8bee376914416d891a791c5aca56e1
```

Its exact DER bytes occur in the unchanged research2 Image. The original installed Novatek module and the new signed module both identify `Build time autogenerated kernel key`, signature hash `sha512`, and `sig_key` `3C:F6:01:76:70:E0:3F:6A:F0:F6:56:54:20:3F:39:B2:F8:06:1F:59`. The `sig_key` value is not the SHA-256 certificate fingerprint; both values are retained separately in the evidence.

The signing code parses the kernel module's appended PKCS#7 trailer. It proves the entire new signed payload is byte-for-byte identical to the previously inspected unsigned module, with SHA-256 `cecbd4709f2e6cbb488586ca24f06de6ffe4f7a27fd15bba5ab4649aa29d3972`. It verifies the old and new detached CMS signatures using the explicitly supplied public certificate. OpenSSL returned `CMS Verification successful` for each. The command's `-noverify` skips a public-CA chain check; it does **not** disable cryptographic signature verification. `-nointern` prevents choosing a different certificate embedded in a CMS object. The local trust link is the exact certificate in the frozen Image plus the matching original signed module.

The signed module retains the same vermagic and all **63 imported symbol CRCs** match the frozen `Module.symvers`. These checks do not substitute for an actual kernel-loader or hardware-probe test.

## Reproduction boundary

[`scripts/research/input/signing/stage_signed.py`](../../../scripts/research/input/signing/stage_signed.py) pins the exact existing build, unsigned artifacts and public certificate. It accepts a fresh output prefix and rejects an existing destination, source overlap, symlinked selected inputs, inventory changes or a different certificate. It does not generate a replacement key when the original key is missing.

```sh
python3 /path/to/repo/scripts/research/input/signing/stage_signed.py \
  --baseline /work/research2-display \
  --input /work/input-integration-v3 \
  --output /work/input-research2-integration-next
```

The recipe belongs to the separate `input/signing/` directory, so it does not change the already executed module-build recipe's input inventory.

This prefix is a kernel/module/DT combination. It contains **no firmware, root filesystem, initramfs or packaged Android boot image**. Those components need a separately recorded system integration. Native display timing, touch/pen behavior, keyboard attachment and wake, CTN730 charging and physical suspend/resume retain the unresolved boundaries documented in the module/DT report. A successful offline signature check does not change any physical-device pass count.
